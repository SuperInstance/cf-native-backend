# B2 — Membrane Worker (TS port of the cell receipt-chain, wake-on-URL)

First deployable proof of "the repo IS the runtime" on Workers + Artifacts.
Branch `b2-ts-artifacts`. Ports `lattice/hello-cell` (B1, Python) to TypeScript.

## What was built

| file | role |
|---|---|
| `worker/src/chain.ts` | the receipt chain, ported 1:1 from `cellgen.py` + the verify walk in `wake.sh`: `fnv1a64`, `canonical`, `appendReceipt`, `verifyChain`, `buildHibernationReceipt` (doubt-ledger 4-field grammar) |
| `worker/src/index.ts` | the Membrane Worker: `GET /cell/<id>` wake-on-URL; `GET /` health |

## The wake path (B2 scope — minimal, honest)

```
GET /cell/<id>?tail=8
  → env.ARTIFACTS.get("cell-<id>")            (disposable repo handle, `using`)
  → repo.readFile({ ref: "main", path: "receipts.txt" })   ┐ memory files
  → repo.readFile({ ref: "main", path: "genesis.json" })   ┘ (working tree never touched)
  → verifyChain(): fnv1a-64 walk genesis basis → tip, O(1) memory + tail ring
  → 200 { awake, chain{positions,tip,tipMatch,countMatch,chainOk,firstBreakAt},
          receipt_tail[], wake{fetch_ms, verify_replay_ms, positions_per_sec} }
    (500 if the chain fails verification; 404 if repo/files missing; 422 scheme mismatch)
```

The Worker holds **no cell state**. A cell exists only as its Artifacts repo
(memory = `receipts.txt` + `genesis.json`); it wakes when its URL is hit.
Deliberately absent (B3/B4): concurrency, fork-per-task, merge surface, UI.

## Artifacts binding — EXACT syntax (verified against official docs)

`worker/wrangler.jsonc`:

```jsonc
{
  "$schema": "node_modules/wrangler/config-schema.json",
  "artifacts": [
    {
      "binding": "ARTIFACTS",
      "namespace": "default"
    }
  ]
}
```

Worker-side surface used here (per docs):

```ts
export interface Env { ARTIFACTS: Artifacts; }

using repo = await env.ARTIFACTS.get("cell-<id>");   // disposable handle
const file = await repo.readFile({ ref: "main", path: "receipts.txt" }); // Blob | null
const text = await file.text();
```

Source URLs (fetched 2026-10-01/02):
- **Workers binding (primary):** https://developers.cloudflare.com/artifacts/api/workers-binding/
- **REST API (control plane):** https://developers.cloudflare.com/artifacts/api/rest-api/
- **Wrangler artifacts commands:** https://developers.cloudflare.com/workers/wrangler/commands/artifacts/
- **Wrangler config schema:** node_modules/wrangler/config-schema.json (local, after `npm i -D wrangler`)

Key doc facts recorded verbatim:
- Binding array entries: `binding` (name) + `namespace`; optional `remote = true` (toml) for remote Artifacts in local dev.
- `get(name)` returns a **disposable repo capability**, not metadata; declare with `using`; call `repo.info()` for metadata.
- `readFile({ref, path})` returns a MIME-typed `Blob | null` (null = missing path or directory).
- Docs note: **Wrangler ≥ 4.145.0** required for generated Artifacts binding types / remote-binding Blob methods in local dev.
- Token minting from the Worker: `repo.createToken("read", 3600)` → `{ plaintext, expiresAt }`.

## Honest limitation — the binding is read-oriented

The Workers binding can create/fork/import/delete repos and **read** git
objects (`readFile`/`readBlob`/`readTree`/`readCommit`/`log`) — but it has
**no write-file/commit method**. Content writes go through the **git protocol**
(push over HTTPS to the repo's `remote` using a repo token from `create()` /
`createToken()`), per https://developers.cloudflare.com/artifacts/api/git-protocol/.
This is fine for B2 (wake = read + verify). **B3 (append/hibernate receipts
from the Worker) must either mint short-lived write tokens and push, or land
writes via an external pusher** — a real design decision, recorded here, not
solved.

## Verification receipts

1. **Type-check:** `npx tsc --noEmit` — **PASS** (strict), against
   `worker-configuration.d.ts` generated by `npx wrangler@latest types`
   (wrangler 4.x latest, 2026-10-01). The generated file contains the real
   `Artifacts` / `ArtifactsRepo` interfaces.
2. **Cross-language parity (MEASURED, this build):** python `cellgen.py --n 5000
   --seed 11` mint → ts `verifyChain` → tip **byte-identical**
   (`c53202562d4e0b22`), count/tip match, `chain_ok=true`; tampered op →
   caught at position 0; `appendReceipt` deterministic.
   Re-run: `npm run parity` inside `worker/` with a cellgen cell dir.
3. **Throughput datapoint (MEASURED, this box, node 22.23):** 100k positions
   verified in **220 ms** (~455k pos/s) vs B1 pure-Python ~2.0 s (~50k pos/s)
   — ≈ **9× faster**. Extrapolated 1M ≈ 2.2 s in-worker (NOT yet measured on
   a real Worker; CPU limits differ).

## What is NOT verified (do not quote as proven)

1. **No live deploy.** The Worker has never run against a real Artifacts
   namespace — no account/namespace was provisioned in this build. `wrangler
   deploy` + a real cell repo push are the next gate. Binding shape comes from
   official docs + wrangler's generated types, not from a served request.
2. **Namespace "default" existence** is assumed from docs examples; whether it
   is auto-created per account is unconfirmed (`wrangler artifacts` / REST
   `POST /artifacts/namespaces` is the fallback).
3. **`ref: "main"`** assumes cell repos are minted with default branch `main`
   (B3's cell-minting path must honor `setDefaultBranch: "main"`).
4. **Worker CPU limits** (default 30 s wall / CPU budget) at 1M positions are
   extrapolated, not measured on Workers runtime.
5. **`using`/Disposable semantics** of the RPC handle compile (generated
   types) but their runtime release behavior is untested without a deploy.
6. **B1 physics pins** (H1–H3) were not re-run here; the TS parity receipt
   (item 2 above) is the only new number this build adds.
